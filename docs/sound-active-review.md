작가(11/27): "어떻게 하면 좀 더 active 한 음악경험 가능한지 검토해보라고 해 — 예컨대 길 위에선 테크노비트처럼 흘러간다거나, 건물별로 약간... 장르? 밴드조합? 처럼 다른 특색이 있다거나 — 지금은 전부 다 너무 앰비언트 해서 둔한 사람은 잘 모르겠대"

**검토만 했다 — 코드는 바꾸지 않았다.** 소리를 틀어 보지도 않았다(Claude 쪽 브라우저는 무음). 아래 숫자는 코드(`lib/sound/engine.ts`, `sequencer.ts`, `harmony.ts`, `signals.ts`, `ParliamentScene.tsx`)와 **프로덕션에 저장된 값**에서 읽었다: anthropocene-redesign, `/v2/mobile`, 폴더 `소리 (V2 · 헤드셋)`, 2026-11-22 15:13 저장 — 관객이 실제로 받는 값이다.

읽은 코드: 리디자인 프로덕션(74d9e64) + 모바일 뷰 랩 브랜치(`claude/future-view-lab-reference-b7bdc2`, dbb1b49). 랩은 소리 파일을 하나도 바꾸지 않았다. 소리에 닿는 랩의 변화는 **걷는 속도** 하나다(§1.3).

## 요약

- **왜 앰비언트인가**: 귀에 닿는 박이 없다(유일한 박 = 길 위의 40–80 Hz 사인, 클릭 없음, 홀로 전부 번짐). 모든 음이 느리게 시작해 길게 번진다(사인·어택 60 ms·긴 릴리즈·에코·잔향 넷). 화성은 걸을 때 마디마다 바뀌어서 오히려 "바뀜"이 안 들린다. 장소가 바뀌면 소리가 **빠지고**(먹먹해짐) 그마저 1–3초에 걸쳐 스며든다. 패치와 식생 노이즈가 어디서나 같은 바닥을 깐다. → 둔한 귀가 알아듣는 **박 · 반복 · 켜짐/꺼짐 · 순간의 대비**가 없다. 랩의 새 모습(걷는 속도 7 → 3)이 들어오면 심장박동은 분당 30으로 더 드물어진다(§1.3).
- **방향 넷**:
  - **A 선명하게** — 지금 음악 그대로, 소리의 모양만(마름, 또렷한 박, 문 소리).
  - **B 길 = 비트** — 16스텝 드럼머신, 길이 많이 밟혔을수록 층이 쌓임, 올라서면 다음 마디 1에 드롭.
  - **C 건물 = 밴드** — 지은 사람들이 멤버, 건물 키의 모드가 장르, 멀리서도 들림.
  - **D 한 삶 = 한 곡** — 장소가 곡의 구간을 고름(열린 땅 = 브레이크다운, 길 = 벌스, 건물 = 후렴, 함께 짓기 = 드롭). 3분 삶 = 팝송 한 곡, 녹음이 그 사람의 곡이 됨.
- 넷 다 **모티프 = 나**, **에포크의 한 키 · 한 박(2 s 마디)** 은 그대로 — 같은 자리의 여러 관객은 같은 마디에 같은 것을 듣는다.
- **제안**: B의 드럼이 B·C·D 공통의 바닥이다. 첫걸음은 스위치 하나 — **`길의 소리: 심장박동 / 비트`**. 그 전에 오늘 **코드 없이 노브만으로** 10분 들어 볼 것(§4.0).

## 1. 지금 왜 앰비언트로 들리나

### 1.1 지금 소리가 반응하는 것 (저장값 기준)

| 상황 | 지금 들리는 것 | 소리의 모양 |
|---|---|---|
| 열린 땅, 혼자 | 내 모티프(마디의 약 56 %에서만), NoiseCraft 패치, 식생 노이즈 | 사인, 느린 어택, 긴 꼬리, 에코·잔향 |
| 길 위 | + 심장박동(장소 코드의 근음) | 폰에서 누르고 걸으면 늘 "뛰기"(아래 1번) → 마디에 두 번 = 분당 60, 쿵-쿵(0.17 s 간격) |
| 건물 근처·안 | 전체가 먹먹해짐(3900 → 800 Hz), 콘크리트 방, 건물의 조성(으뜸 / 고리에선 도미넌트) | 빼기 — 밝기가 줄어듦 |
| 사람 곁 | 그 사람의 모티프(가까운 4명까지), 머물면 부르고 답하기 · 패드 · 홀 | 봇은 흐림: 사인, ~1.2 kHz 위 잘림, ±14센트 흔들림 |
| 함께 짓기 시작 | 도착의 종지: 도미넌트 마디(파도 밀려옴) → 으뜸(파도 부서짐, 홀 열림) | 유일하게 "사건"으로 들리는 순간 — 8마디에 한 번까지 |
| 이름 · 찾은 말 · 대답 | 한 사람의 멜로디가 홀로 / 크게(대답 ×2.2) | 사건 |

### 1.2 원인 여섯

**1. 박이 귀에 닿지 않는다.**
- 소리 전체에서 규칙적인 박은 길 위의 심장박동 하나다(`bassNote`). 음높이는 근음을 **40–80 Hz**로 끌어내린 사인, 서브는 그 한 옥타브 아래(20–40 Hz), "살"을 붙이는 노이즈는 220 Hz 아래만, 어택 25 ms. 저장값 `bassDrop` **0** = 음정 낙하 없음 — 킥의 "딱"이 나오는 곳이 바로 이 낙하다. 그래서 220 Hz 위에는 거의 아무것도 없다.
- 귀는 50 Hz에서 1–3 kHz보다 수십 dB 둔하고(등청감 곡선), 폰 이어폰·작은 헤드폰은 그 대역을 잘 내지 못한다 → **들리기보다 느껴지는** 박. 게다가 저장값 `bassSpread` **1** = 3.2 s 홀로 전부 보냄 → 박의 윤곽까지 번진다.
- 길 밖에는 박이 아예 없다. 모티프가 그리드 위에 있긴 하지만 마디의 약 56 %에서만 울리고(`motifEvery` 1.8, 마디마다 확률), 세 번에 한 번 옥타브가 옮겨지고(`motifOctaveEvery` 3), 자유로울 땐 ±40 ms 흔들린다(`jitterMax`) → 같은 것이 반복되지 않으니 귀가 붙잡을 패턴이 없다.
- 폰에서는 누르면 걷는다 = 언제나 최고 속도 **7**(지금 프로덕션: `ParliamentScene` 전진 7, `speedMax` 7). "걷기"와 "뛰기"의 구별이 없어서 밀도는 늘 "뛰기"(마디에 두 번)다. 걸음으로 바꿀 수 있는 건 사실상 **선다 / 걷는다** 둘뿐이다. 랩의 새 모습에서는 속도가 3이라 이야기가 또 달라진다(§1.3).

**2. 모든 소리가 느리게 시작해 길게 번진다.**
- 모티프: 사인, 어택 60 ms, 서스테인 0.8, 릴리즈 = 0.15 s + 음 길이의 1.2배(다음 음과 겹침), 에코 0.6(3/8마디 = 0.75 s 뒤, 되먹임 0.3), 먼 공간(2.4 s), 트레몰로 · 숨.
- 열린 땅에서도 마스터 저역통과가 **3900 Hz**(`lpOpen`; 코드 기본은 5900) → 고음의 윤곽이 없다.
- 방이 넷(열린 땅 1.2 s, 콘크리트 1.6 s, 홀 3.2 s, 먼 공간 2.4 s)이고 심장박동 · 파도 · 식생 노이즈는 홀로 직접 간다.
- 느린 어택 + 긴 꼬리 + 젖은 공간 = 앰비언트의 정의 그대로다.

**3. 화성이 쉬지 않고 흘러서, 바뀜이 들리지 않는다.**
- 저장값 `bandCells` **5** = 땅의 코드 띠가 (x+z) 방향으로 6 월드. 폰 속도 7로 걸으면 x나 z 방향으로는 0.86 s, 대각선으로는 0.6 s마다 띠 하나를 지난다(띠와 나란히 걸을 때만 머문다) → **2초 마디마다 다른 코드**, 걷는 방향에 따라 진행 방향도 뒤집힌다. 늘 바뀌니 "바뀌었다"가 없다.
- 건물 존 안에서만 코드가 멈춘다(으뜸 / 고리에선 도미넌트) — 지금 가장 또렷한 대비인데, 음높이로만 말한다.

**4. 장소가 바뀌면 소리가 빠지고, 그것도 천천히 스며든다.**
- 건물에 들어서는 것 = 저역통과가 3900 → 800 Hz로 내려가고 콘크리트 방이 열림. 둔한 귀에는 "작아졌다 / 답답해졌다"로 들린다 — 무언가가 **생기는** 게 아니라 **빠진다**.
- 0.5 s마다 오는 신호를 시상수 0.25–0.8 s로 따라가니 변화는 1–3 s에 걸쳐 스며들고, 조성은 다음 마디에 바뀐다.
- 건물의 조성권은 존 반경 8 + 0.6√질량(최대 18)에 고리 8을 더해, 중심에서 최대 26 월드 밖부터 시작된다 → 문턱이 없다.

**5. 어디서나 같은 바닥이 깔린다.**
- 저장값 악기 = **둘 다**: 작가의 NoiseCraft 패치가 숨은 iframe에서 늘 돈다 — 랜덤 트리거(25 %·3 Hz, 20 %·0.75 Hz), 0.1 Hz LFO와 40초 엔벨로프로 숨 쉬는 필터, 노브 매핑은 0.25 s에 범위의 4 % 이하로 미끄러진다(끝에서 끝까지 ~6 s). 생성형 앰비언트 기계 그 자체이고, 어디에 서 있든 비슷하게 깔린다.
- 식생 노이즈(2.4 kHz 띠)도 늘 있다.
- 이 바닥이 장소 사이의 차이를 덮는다.

**6. 사건은 드물다.**
- 또렷한 순간(이름, 찾은 말, 대답, 도착의 종지)은 있다. 그러나 도착은 내 무게가 남의 건물에 처음 셈될 때(또는 함께 서 있는 곁에 건물이 태어날 때)만, 8마디에 한 번까지다. 한 삶은 180 s = 90마디라 한두 번이 고작이다.
- 3분은 규칙을 배우기에 짧다 → 소리는 처음 10초 안에 "아, 이게 길이구나"가 되어야 한다.

### 1.3 랩의 새 모습이 들어오면: 걷는 속도 7 → 3

랩 브랜치에서는 새 모습(길거리)이 켜지면 플레이어의 걷는 속도가 랩의 `scan (present) · 현재의 장소 › 눈 › 걷는 속도`를 따른다(`usePersonalVisuals.ts` `walkSpeed`; 기본 2.5, `/lab/mobile`에 저장된 값 **3**). 새 모습이 꺼져 있으면 지금처럼 7. 소리 쪽 `뛰는 속도`(`speedMax`)는 7 그대로이므로:

- 3 / 7 = 0.43 → 밀도 1: 걸어도 심장박동은 **마디에 한 번 = 분당 30**(지금의 절반). 박이 더 드물어진다.
- 코드 띠는 1.4–2 s마다 → 여전히 거의 마디마다 새 코드.
- 건물의 조성권(중심에서 최대 26 월드)을 가로지르는 데 ~9 s — 문턱은 더 흐려진다.
- 걸음이 곧 "걷기"(서 있음과의 차이)라는 점은 같다.

→ 랩의 모습이 들어가면 지금 소리는 **더 느리고 더 앰비언트**해진다. 어느 방향을 고르든 소리가 "걷는 중"을 읽는 기준(`speedMax`의 비율)을 걷는 속도에 묶거나 "움직임 있음/없음"으로 바꿔야 한다 — 아래 방향들은 모두 그렇게 가정한다.

**정리**: 지금 소리는 장소를 **음높이와 음색의 미세한 차이**로 말한다. 둔한 귀가 알아듣는 건 **박(펄스) · 반복 · 켜짐/꺼짐 · 순간의 대비**다. 아래 방향들은 모두 이 넷을 장소에 붙이는 방법이다.

## 2. 방향 넷

**넷 다 지키는 것**
- **한 박**: 마디는 지금처럼 에포크부터 벽시계로 센다(`barClock`) — 모든 관객 · 봇 · 탭이 같은 마디. 2 s 마디를 4/4로 읽으면 **120 BPM**(테크노는 보통 125–135; 마디 1.85 s = 약 130). 드럼은 이 마디를 16스텝(0.125 s)으로 쪼갤 뿐, 템포를 개인이 바꾸지 않는다 → 같은 건물 안의 두 관객은 같은 박에 같은 걸 듣는다.
- **한 키**: 세계의 키(`worldKey`)와 건물의 키(`bestKey`, 기여자들에게서) 그대로.
- **모티프 = 나**: 내 음형과 리듬 셀은 어느 방향에서든 나의 리드 라인이다. 바뀌는 건 그 밑의 반주와 소리의 모양(악기 · 밀도)뿐.
- **전환은 마디 위에서**: 신호(0.5 s) → 다음 마디 첫 박. 늦는 게 아니라 "1에 떨어진다"가 음악의 문법이다(한 박 전에 필 · 라이저로 미리 알림).

### A. 선명하게 — 지금 음악 그대로, 소리의 모양만

새 장르 없이, 지금의 규칙이 **들리게** 고친다.

- **열린 땅**: 모티프가 짧고 마른 소리(어택 5–10 ms, 짧은 릴리즈, 에코 · 잔향 1/3)로 **매 마디 똑같이** 반복(확률 · 옥타브 이동 끔). 패치는 열린 땅에서만 얇게, 또는 끔.
- **길에 올라섬**: 심장박동이 **매 박**(마디에 넷)으로, "딱" 하는 클릭(2–4 kHz, 몇 ms)과 100–150 Hz 펀치가 붙고 잔향은 조금 → 폰 이어폰에서도 들리는 걸음. 내려서면 박이 멈춤.
- **건물에 들어섬**: 경계를 넘는 마디 첫 박에 **문 소리**(건물 코드의 짧은 스탭 한 번) + 먹먹함이 한 박 안에 닫힘(지금은 1–3 s). 건물의 코드가 박에 맞춰 펄스.
- **사람 곁**: 가장 가까운 한 사람의 모티프가 흐림 없이 앞으로, 나머지는 뒤로.
- **화성**: 코드 띠를 넓혀(예: 12셀) 한 코드가 2–4마디 머물게 → 바뀜이 들림.

**비용 · 위험**
- 가장 싸다. 대부분 노브, 코드는 클릭 층 · 박의 수 · 문 소리 정도(심장박동 한 타 = 노드 7개 → 클릭에 2개 더). 샘플 없음. 폰 부담은 지금과 같다.
- 더 또렷해지지만 여전히 같은 "장르" — 작가가 말한 "흘러간다", "특색"까지는 못 간다. 다만 다른 방향에도 필요한 손질이라 버려지지 않는다.

### B. 길 = 비트 — 길이 그루브가 된다

길의 세기(`pathP` = 얼마나 많이 밟혔나)가 곧 **층의 수**. 많이 밟힌 길일수록 판이 커진다.

- **열린 땅**: **박 없음** — 지금의 앰비언트(모티프 · 식생 · 패치)를 그대로 둔다. 이 대비가 핵심이다.
- **길에 올라섬**: 그 마디 마지막 박에 짧은 필(스네어 롤 / 노이즈 라이저) → 다음 마디 **1에 킥이 떨어진다**(드롭). 네 박 킥(포 온 더 플로어). 길이 셀수록 층이 붙는다: 0.15 킥 → 0.4 + 오프비트 햇 → 0.7 + 2·4박 클랩과 16분 햇 → 가장 센 길 + 장소 코드의 근음으로 8분 베이스라인.
  - 걷는 중 = 전부, 길 위에 서 있음 = 킥만 먹먹하게(대기).
  - 내 리듬 셀(`onsets`)이 내 햇/퍼커션 패턴 → 비트 속에서도 나는 나의 박자.
  - 킥마다 모티프 · 타인이 눌림(지금의 `bassDuck` = 테크노의 사이드체인 펌핑 그대로).
- **길에서 내려섬**: 한 마디 동안 고역이 닫히며 비트가 멀어지고 끝.
- **건물**: 존 안 = 하프타임 덥 테크노 — 킥은 반으로, 건물 코드의 스탭에 긴 딜레이. 밖에서 다가가면 그 방의 비트가 벽 너머처럼 먹먹하게, 들어서면 열림.
- **사람 곁**: 그 사람의 모티프가 짧은 신스 스탭으로 그루브에 들어옴. 사람이 많을수록 퍼커션이 하나씩 더(각자의 리듬 셀) → 군중 = 폴리리듬.
- **함께 짓기**: 도착의 종지가 **빌드업 → 드롭**이 된다(도미넌트 마디 = 스네어 롤 + 라이저 + 파도, 으뜸 첫 박 = 모든 층). 지금의 구조(`nextArrival`) 그대로.

**비용 · 위험**
- 드럼은 샘플 없이 합성: 시작할 때 `OfflineAudioContext`로 킥 · 햇 · 클랩 · 스네어를 한 번 구워 버퍼로 두면 한 타 = 노드 2개(지금 모티프 한 음 ≈ 노드 12개, 심장박동 한 타 = 7개). 최악의 마디(16스텝 × 3층)도 초당 노드 50개 안팎 → 폰에서 지금보다 무겁지 않을 것으로 본다. 단, **폰 실기기에서 잰 적은 아직 없다**(sound-logic §11). 라이선스 문제 없음.
- 지연: 길을 밟고 0.5–2.5 s 뒤 첫 박 — 드롭으로 들리므로 괜찮다. 발소리를 박에 붙이려면 0.5 s 신호가 아니라 플레이어의 속도를 프레임마다 읽어 다음 16분에 놓아야 한다(가능, 작은 일).
- **장르 클리셰**: 클럽/게임처럼 들려 작품의 결(지층, 표본, 조용함)과 부딪칠 수 있다. 대안: 테크노의 **문법**(포 온 더 플로어, 층 쌓기, 드롭)만 가져오고 소리 재료는 작품의 것(지금의 쿵, 전파 사인, 노이즈)으로.
- 패치와 비트가 겹치면 시끄러워짐 → 길 위에선 패치를 낮추거나 끔.
- 기존 노브: 비트일 때 심장박동 전용 노브(`bassDub` · `bassDrop` · `bassSpread`)는 안 읽힘 → 숨김. `bassLevel`은 비트 세기로.

### C. 건물 = 밴드 — 지은 사람들이 멤버

건물마다 고정된 라인업과 장르가 있고, 그것이 **그 건물의 데이터에서** 나온다 → 같은 건물은 누구에게나, 언제 가도 같은 밴드.

- **멤버 = 기여자**: `who`(넣은 양 순)의 앞 1–5명이 파트를 맡는다 — 1위 = 베이스(그 사람의 모티프를 낮은 음역 리프로), 2위 = 건반/코드 스탭(그 사람의 리듬 셀로), 3위 = 리드(모티프 그대로), 4위 = 드럼 패턴(리듬 셀), 5위 = 패드/목소리. 혼자 지은 건물 = 솔로, 둘 = 듀오, 다섯 이상 = 밴드.
- **장르 = 건물 키의 모드**(`bestKey`): 에올리안 → 미니멀/다크 테크노(킥 · 서브 · 금속 스탭), 도리안 → 펑크/브로큰비트(당김음, 클라비넷풍), 믹솔리디안 → 모토릭(곧은 8분, 오르간 드론), 이오니안 → 하우스(피아노 코드, 클랩).
- **그 밖의 데이터**: 질량 · 높이 = 몇 명이 동시에 연주하나. 닳음(`h/raw`) = 테이프처럼 늘어지고 끊김. 버려짐(`lastS`가 오래됨) = 드럼 없이 메아리만 남은 유령 밴드. 마을의 성격(`VillageSite.ch`: 정착/떠돎, 크기)으로 지역 전체에 "씬"을 줄 수도 있다(정착 마을 = 곧은 4/4, 떠도는 마을 = 손 타악기).
- **들리는 것**: 멀리서 건물의 밴드가 그 자리에서(패너 하나) 벽 너머처럼 먹먹하게 → **귀로 찾아갈 수 있다**. 존에 들어서면 벽이 열리고 밴드가 가까이. 두 건물 사이에선 두 밴드가 교차(키가 가까운 건물끼리는 자연스럽게 — `keyDistance`). 길 = 건물 사이를 잇는 단순한 박(B의 킥 · 햇 정도).
- **사람 곁**: 그 사람의 모티프가 게스트 솔로로.
- **함께 짓기**: 내 무게가 셈되는 순간 내 모티프가 그 건물의 라인업에 들어간다(나는 이제 멤버). 나중에 그 건물을 지나는 다른 관객도 내 리프를 듣는다 — 작품의 "흔적" 논리와 가장 잘 맞는다.

**비용 · 위험**
- 가장 크다. 악기 5–8종이 필요하다. 합성만으로(지금의 감산 · FM + 새 드럼) 가거나, 실제 악기 장르(재즈 트리오, 록 밴드)를 원하면 샘플.
- 샘플은 CC0 라이브러리(예: VCSL, VSCO 2 Community Edition — 쓰기 전에 각 라이선스 파일 확인)로 악기당 수 MB, 필요할 때 로딩. 상용 샘플팩은 대개 "음악 제작에 사용"은 허락하되 **원본 파일 재배포를 금지**하는데, 웹은 그 파일을 관객의 브라우저로 보내므로 재배포에 걸릴 수 있다 → 피한다.
- 목소리 수: 한 번에 밴드 하나(+ 옆 건물 하나 페이드) × 파트 5 × 마디당 몇 음. 지금의 `note()`(음마다 노드 ~12개)로는 무겁다 → 미리 구운 한 음을 `playbackRate`로 옮겨 쓰는 가벼운 악기(음마다 노드 2개)가 필요하다.
- 매핑이 안정해야 한다: 누가 벽돌 하나 더 얹을 때마다 밴드가 바뀌면 안 됨 → `bestKey`처럼 문턱을 두거나 "창립 멤버"를 고정. 건물이 합쳐지면 밴드가 갑자기 바뀜(합쳐짐 자체를 사건으로 들려줄 수도).
- 합성 악기만으로는 "장르"가 기대만큼 또렷하지 않을 수 있다.
- 기존 노브: `건물의 조성` · `건물 바깥 고리 폭` · `조성이 바뀌는 문턱`은 그대로 쓰이고, 밴드 폴더가 새로 생긴다(파트별 크기, 벽 너머의 먹먹함, 밴드가 들리는 거리).

### D. 한 삶 = 한 곡 — 장소가 곡의 구간을 고른다

세계가 한 곡을 늘 연주하고(한 키, 한 박), **내가 선 곳이 지금 어느 구간인지**를 고른다(게임 음악의 "층 켜고 끄기 + 구간 이동"). 팝의 구조 — 인트로, 벌스, 빌드업, 드롭, 브레이크다운, 아웃트로 — 는 누구나 몸으로 안다.

| 장소 / 순간 | 곡의 구간 | 들리는 것 |
|---|---|---|
| 이름 | 인트로 | 지금의 `announce` |
| 열린 땅 | 브레이크다운 | 패드와 내 모티프, 박 없음 |
| 길 | 벌스 | 드럼과 베이스가 들어옴(B의 층) |
| 건물 | 후렴 | 모든 층, 건물 키의 4마디 코드 진행이 훅 |
| 사람 곁 | 피처링 | 그 사람의 모티프가 대선율 |
| 함께 짓기 | 빌드업 → 드롭 | 도착의 종지 |
| 죽어감 / 죽음 | 아웃트로 | 지금의 먹먹해짐 → 마지막 코드의 잔향 |

- 전환은 모두 마디 위에서, 한 박 전에 필/라이저.
- 180 s 삶은 팝송 한 곡의 길이다 → **삶의 녹음(표본 카드의 QR)이 그 사람의 곡이 된다.**

**비용 · 위험**
- 악기와 CPU는 B와 같다(드럼, 베이스, 코드, 모티프). 일은 편곡의 상태(지금 어느 구간)와 전환(필 · 라이저 · 드롭)에 있다.
- 장소의 "개성"은 C보다 약하다(건물은 모두 "후렴"). 미리 만든 곡처럼, 루프처럼 들릴 수 있다. 질림은 삶이 3분이라 덜하다.

## 4. 제안 — 가장 작은 첫걸음

### 4.0 오늘, 코드 없이 (10분)

`/v2/mobile`(패널이 있는 주소)에서 `소리 (V2 · 헤드셋)` 폴더의 노브를 돌려 듣는다. **save를 누르지 말 것** — 이 페이지의 저장값은 서버로 가서 관객 모두가 받는다. 다 듣고 reload(또는 새로고침)를 누르면 원래 값으로 돌아간다.

| 노브 | 지금 | 들어볼 값 | 듣는 것 |
|---|---|---|---|
| 악기 | 둘 다 | Web Audio만 | 패치의 바닥이 빠지면 얼마나 또렷해지나 |
| 땅의 띠 폭 | 5 | 12 | 코드가 몇 마디 머묾 → 바뀜이 들리나 |
| 내 모티프: 평균 몇 마디에 한 번 | 1.8 | 1 | 매 마디 같은 음형 |
| 내 모티프: 옥타브 이동 | 3 | 0 | 같은 음역에서 반복 |
| 모티프 에코 | 0.6 | 0.2 | 마름 |
| (세부) 먼 공간 | 0.5 | 0.15 | 마름 |
| (세부) 릴리즈 | 1.2 | 0.4 | 음 사이에 틈 |
| (세부) 어택 | 60 | 8 | 또렷한 시작 |
| 심장박동: 음정 낙하 | 0 | 0.7 | 박의 "딱" |
| 심장박동: 퍼짐 | 1 | 0.3 | 박의 윤곽 |
| 열린 땅의 밝기 | 3900 | 8000 | 고음의 윤곽 |

(세부) = 접혀 있는 `모티프 음색 (세부)` 폴더 안.

이것만으로 A의 절반이 들린다. 여기서도 "여전히 앰비언트"라면 원인은 소리의 모양이 아니라 **구조**(박 · 층 · 전환이 없음)다 → 4.1로.

### 4.1 첫 커밋: 스위치 `길의 소리 — 심장박동 / 비트`

B의 가장 작은 판. 기본값은 지금의 심장박동 — 작가가 같은 걸음 위에서 스위치로 비교한다.

**비트일 때**
- 길 위(`pathP ≥ bassFrom`, 지금과 같은 문턱): 마디마다 킥 넷(120 BPM). 킥 = 지금 심장박동의 몸통(근음) + 클릭 + 펀치, 잔향은 조금.
- 걷는 중(누르고 있음 — 속도의 비율이 아니라 "움직임 있음"으로 읽어서, 지금의 7이든 랩의 3이든 같게): + 오프비트 햇. 길 위에 서 있음: 킥만.
- 센 길(`pathP` ≥ 0.6): + 2·4박 클랩.
- 길에 올라설 때: 그 마디 마지막 박에 필(스네어 넷) → 다음 마디 1에 킥. 내려설 때: 한 마디 동안 닫히며 빠짐.
- 킥마다 모티프 · 타인이 눌림(`bassDuck` 그대로 — 펌핑).
- 길 밖 · 건물 · 사람 · 도착은 **지금과 같음** → 대비가 비트 하나만으로 생기는지 들을 수 있다.

**노브**
- 숨김(비트일 때 안 읽힘): `심장박동: 두 번째 박 세기`(`bassDub`), `심장박동: 음정 낙하`(`bassDrop`), `심장박동: 퍼짐`(`bassSpread`).
- 이름만 바뀌어 남음: `길의 심장박동 세기`(`bassLevel`) → 비트 세기. 그대로: `심장박동이 시작되는 길의 세기`(`bassFrom`), `…모티프 · 타인이 눌리는 정도`(`bassDuck`), `길로 치는 반경`(`pathRadius`).
- 새로: `비트 층`(킥 / + 햇 / + 클랩), `킥의 클릭`, `비트 잔향`, `들어설 때 필`(켬/끔).

**비용**: 드럼 넷을 시작할 때 한 번 구움(샘플 없음), 한 타 = 노드 2개. 성능 확인은 Claude 몫(무음 헤드리스로 마디 빠짐 · 메인 스레드).

**들어 보는 순서**: 열린 땅에서 10초 → 길로(첫 박의 드롭) → 길 위에 섬(햇이 빠짐) → 다시 걸음 → 길 밖으로(빠짐) → 건물 쪽으로.
판단할 것: (1) 둔한 사람도 길을 "들을" 수 있나, (2) 작품의 결과 맞나 — 테크노의 소리까지 갈지, 문법만 가져올지.

## 5. 작가가 정할 것

1. **방향**: B 다음에 C(건물 = 밴드)로 갈지 D(한 삶 = 한 곡)로 갈지 — 둘 다 B의 드럼을 바닥으로 쓴다. A의 손질은 어느 쪽이든 들어간다.
2. **템포**: 2 s 마디 = 120 BPM 그대로? 테크노답게 1.85 s(약 130)? — 마디 길이를 바꾸면 모티프도 빨라진다. 그리고 벽의 내 표시와 개인뷰의 기호는 고정된 250 ms 스텝(`lib/parliament/glyph.ts` `STEP_MS` = 2 s 마디, `docs/me-marker.md`)으로 깜빡이므로 같이 바꿔야 소리와 어긋나지 않는다.
3. **NoiseCraft 패치**: 계속 늘 깔지, 열린 땅(브레이크다운)에만 둘지, 뺄지.
4. **소리의 재료**: 합성만(작품의 쿵 · 전파 · 노이즈로 테크노의 문법) vs 장르의 소리(808 킥, 하우스 피아노 — 샘플이면 CC0만).
