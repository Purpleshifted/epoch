# 사운드 로직 — 살아 있는 문서

작품의 소리가 **왜** 그렇게 나는지를 규칙 단위로 적는다. 코드가 바뀌면 **같은 커밋에서** 이 문서도 바뀐다. 맨 아래 변경 이력에 날짜와 무엇이 바뀌었는지 남긴다. 새 세션은 `docs/sound-handoff.md`(배경)와 이 문서(현재 규칙)를 읽고 시작한다.

코드: `apps/web/src/lib/sound/` (순수 로직 + Web Audio 엔진), `apps/web/src/components/parliament/useSound.ts` (Leva 노브와 시작), `RoleField.tsx` (신호 공급). 테스트: `lib/sound/*.test.ts`.

**v4 (2026-10-15 밤부터, 브랜치 `feature/sound-v4`)**: 이 문서의 소리(10/14 Web Audio 판 = 작가가 말하는 "가벼운 버전")가 출발점이고, 그 위에 요소를 **하나씩** 붙인다(§14의 순서). 한 요소를 붙일 때마다 작가의 유저 테스트를 받고 나서 다음으로 간다. 그동안 만들어 둔 풍성한 요소들은 `feature/sound` 브랜치(창고)에 있다 — 거기서 필요한 것만 옮겨 적는다.

## 1. 목표 경험

- **헤드셋(개인 뷰, `/v2/mobile`)**: 내 라이트모티프가 주인공. 걸으면 리듬이 되고, 길을 따르면 베이스가 받쳐 주며 화성에 붙고, 누군가와 머물면 화음과 부르고 답하기가 생기고, 그 사람의 선율이 내 선율로 스며든다. 건물 근처는 먹먹하고, 풀밭은 밝은 잡음이 깔린다. → **다채롭고, 음악적이고, 내 행위의 결과가 들린다.**
- **전체 뷰(전시장 스피커, 계획)**: 같은 사건들이 시간의 크기로 접혀 저음 드론 한 줄이 된다 (§10).
- 작가 피드백(2026-10-14): 첫 버전(미세음정 ±90센트의 아르페지오)은 단조롭고 흥미롭지 않았다. **길에 맞춰 움직이거나 건물을 지을 때 화성적 만족**이 있어야 하고, **다른 참가자·봇의 멜로디와 상호작용해 변주**가 생겨야 하며, "소리 경험"이 아니라 **음악적 경험**이어야 한다. intersection/umwelt의 NoiseCraft 시퀀서 논리(공유 클록, 성부 = 참가자, 사람의 열로 만드는 진행)를 되살릴 것.

설계 원칙 (direction-2026-10-10 §1): 개인 뷰는 전체 뷰의 정보를 "덜" 보여주는 게 아니라 **다른 종류**(지금·여기·감각)로 보여준다. 소리도 비주얼처럼 **같은 이벤트 로그의 fold**다.

## 2. 신호 — `signals.ts`

`personalSignals()`가 0.5초마다 (RoleField의 fold 직후) 이벤트 로그·fold 스냅샷·스트레스 맵에서 계산. 순수 함수.

| 신호 | 뜻 | 출처 |
|---|---|---|
| `x, z` | 내 위치 | 플레이어 |
| `speed` | 걷기 속도 (월드/s) | 플레이어 속도 |
| `stay` | 0 걷는 중 … 1 머묾: 최근 `staySec`(6 s) 동안 `stayRadius`(1.5)를 안 벗어남 | 내 이벤트 |
| `neighbours` | 귀에 닿는 사람들 (가까운 순): 거리, 방위, 봇 여부. `recentSec`(4 s) 안의 마지막 샘플, 미래(s > 내 시각)는 제외 | 다른 사람의 이벤트 |
| `pathP` | 발밑 셀의 길 강도 0..1 | `snap.paths` |
| `sealed` | 콘크리트의 가까움 0..1 (`sealRadius` 3 안에서 선형) | `snap.slabs` (h ≥ 0.15) |
| `grass` | 주변 3×3 셀의 식생 밀도 평균 | `grassDensity` (nature.ts) |

파생값 (sequencer.ts):
- `company = min(1, 이웃 수 / 2)`
- **`lock = max(pathP, stay × company)`** — 장소가 내 음을 코드로 끌어당기는 정도 (§3).

## 3. 조성 장 — `harmony.ts`

첫 버전이 단조로웠던 이유: 무작위 중심음 둘레의 미세음정은 서로 **해결될 수 없는** 음정이라, 길을 따라가도 함께 지어도 소리가 달라질 수 없었다. 그래서 모든 음높이는 하나의 **공유된 조성 장**에서 나온다.

- **월드 키** `worldKey(epoch)`: 에포크(세계가 새로 시작된 시각)를 시드로 으뜸음(12개 중 하나)과 모드 하나. 모드는 umwelt `chord_library`의 7개 중 가운데 넷(Aeolian, Dorian, Mixolydian, Ionian)에서 고른다 — 양끝(Locrian, Lydian)은 시큼하거나 달아서 제외. 같은 에포크의 모든 방문자·봇·탭이 같은 키를 쓴다 → 서로 **온음계적**으로 어울리는 것이 규칙 이전의 전제.
- **진행**: 마르코프 코드 진행(umwelt의 MAJOR/MINOR 표) 16개를 에포크 시드로 미리 뽑아 땅 위에 **띠**로 깐다. 띠는 `x + z` 방향으로 `bandCells`(4셀 = 4.8 월드)마다 바뀌고 16띠 뒤에 감긴다. 어느 방향으로 걷든 진행을 통과한다. **걷기 = 진행, 서 있기 = 한 코드.**
- **장소의 코드** `placeChord(key, x, z)`: 그 띠의 도수(0..6)로 모드 위에 3도를 4개 쌓은 7화음 (`chordSize` 4). 이름은 `chordName` (예: `Am7`, `Dbm7b5`).
- **lock**: 음을 코드톤 중 가장 가까운 것으로 `snapToClasses`. 확률 = lock, 음마다 독립, 마디 번호로 재현 가능.

## 4. 모티프 — `motif.ts`

방문자 id의 순수 함수 (`makeMotif`). 같은 사람은 어느 뷰·어느 탭에서나 같은 소리.

| 요소 | 뽑는 법 | 범위 |
|---|---|---|
| 음역 `base` | 균등 | MIDI 50 (D3) … 74 (D5) |
| 윤곽 `degrees` | 0에서 시작, 1–3도씩 오르내리는 걸음, 연속 반복 없음 | 3–5개, 대략 한 옥타브 안 |
| 리듬 셀 `onsets` | 8스텝 중 n개 (첫 음은 항상 다운비트) | 서로 다른 스텝 |
| 색 `colour` | 상수 미세음정 | ±12 센트 |
| 템포 비 `tempoScale` | 로그 균등 | 1/1.33 … 1.33 (지금 그리드에서는 안 씀, §5) |
| 음색 `timbre` | 0 어두움(사인) … 1 밝음(옥타브 배음) | 0..1 |
| `centroid` | `base`의 Hz — 기획서의 "중심음"; 전체 뷰의 부분음은 이걸 옥타브 내림 (`partialOf`) | |

`realize(motif, key, chord, lock, cycle)`: 음역을 그 키의 가장 가까운 음계음에 얹고(그 음이 그 목소리의 0도), 도수를 음계 위에서 세어 MIDI로, lock으로 코드톤에 스냅, 자유로울수록(lock 0) `freeCents`(±35) 흔들림. 음 길이는 다음 onset까지의 85 %.

미세음정은 이제 **색**일 뿐이다 (기획서 §3.1의 "미세음정 3–5개"는 윤곽 + 색으로 해석).

## 5. 그리드와 마디 계획 — `sequencer.ts`

intersection/umwelt의 NoiseCraft 시퀀서 논리 이식 (`noisecraft/public/sequencer-logic.js`). 신시사이저는 Web Audio (§8).

- **그리드**: 한 마디 `barSec`(2 s) = 8스텝(16분음표). 마디 번호는 **에포크부터 벽시계**로 센다 → 모든 탭·봇·뷰가 같은 박자. 그리드 밖에서는 아무것도 울리지 않는다 (자유로울 때 `jitterMax` ≤ 30 ms의 휴머나이즈만).
- **밀도** `density(speed)`: 템포는 공유 박자라 바꾸지 않는다. 대신 모티프가 **얼마나 자주 돌아오는가**: 멈춤(속도 < speedMax의 12 %) = 두 마디에 한 번(짝수 마디), 걷기 = 매 마디, 뛰기(≥ 75 %) = 한 마디에 두 번(반으로 압축).
- **베이스**: `pathP ≥ bassFrom`(0.25)이면 다운비트에 장소 코드의 근음 (MIDI 36–47, 사인 + 짧은 피치 드롭). 뛰면 반 마디에도. 세기 ∝ pathP. **길을 따르는 리듬.**
- **성부 = 참가자**: 귀에 닿는 사람마다 목소리 하나, 자기 모티프를 **같은 그리드**에서, 같은 장소의 lock으로.
- **부르고 답하기**: `stay > 0.5`이고 이웃이 있으면 마디가 번갈아 간다 — 짝수 마디 나(+가장 가까운 사람이 조용히 함께), 홀수 마디 가장 가까운 사람 혼자(lock ≥ 0.8로 코드에 붙어 "답"). 걷는 중엔 모두 동시에.
- **패드**: `stay × company > 0.2`이면 장소 코드(근음 한 옥타브 아래 + 코드톤 4개, MIDI 48–59)를 마디마다 다시 조율하며 지속. **건물이 태어나는 소리.**
- **변주 투입**: 가장 가까운 사람의 `closeness`(§6)만큼 내 모티프에 그 사람 것이 섞인다 (`blend`). Magenta 프레이즈가 와 있으면 4마디 동안 그것이 내 마디를 대신한다.

| 상황 | lock | 밀도 | 베이스 | 성부 | 패드 |
|---|---|---|---|---|---|
| 혼자, 풀밭, 서 있음 | 0 | ×0.5 | — | 나 | — |
| 혼자, 길 위, 걷기 | pathP | ×1 | 근음 | 나 | — |
| 여럿, 걷기 | pathP | ×1/×2 | 길이면 | 모두 동시 | — |
| 여럿, 머묾 (짓기) | stay·company | ×0.5 | — | 나 / 가장 가까운 이 번갈아 | 코드 지속 |

## 6. 변주 — `variation.ts`, `magenta.ts`

- **closeness** (엔진이 유지): 이웃이 `hearRadius`의 절반 안에 있으면 초당 +0.12, 아니면 −0.08, 0..1. "얼마나 오래, 얼마나 가까이".
- **blend(mine, theirs, amount, bar)**: 음 자리마다 확률 amount로 그 사람의 도수; amount > 0.5면 그 사람의 리듬 셀(과 음 수)까지. **내 음역은 유지** — 여전히 내 목소리. 마디 번호로 재현 가능.
- **Magenta** (umwelt `MusicEngine.ts`의 `evalSequenceMorpher`/`evalMelodyGen` 이식, 선택):
  - 첫 제스처 4초 뒤 `@magenta/music` + 체크포인트(mel_2bar_small, chord_pitches_improv; Google 버킷, 네트워크 필요)를 동적 로드. 실패하면 조용히 절차적 변주만.
  - 프레이즈 = 4마디 = 32스텝 (MIDI, 0 = 새 음 없음). Magenta에는 120 QPM·4분음표당 4스텝·음역 48–83으로 보낸다.
  - **VAE 보간**: 가장 가까운 사람의 closeness ≥ 0.5이면 내 다음 4마디 ↔ 그 사람의 4마디를 잠재공간에서 보간 (0, ¼, ½, ¾, 1 중 closeness에 가장 가까운 것). 결과가 오면 그때부터 4마디 동안 내 목소리가 된다. 요청 키로 캐시, 같은 요청 동시 1회.
  - **RNN 즉흥**: lock ≥ 0.6이 2마디 이상 이어지면 내 프레이즈를 시드로 장소 코드(`magentaChordName`으로 Magenta가 확실히 아는 이름: '', m, 7, m7, maj7) 위에서 32스텝 이어 받는다.
  - 프레이즈 하나 뒤에는 두 마디 쉼(원래 모티프로 복귀) 후 다시 요청 가능.

## 7. 공간화와 공간 — `engine.ts`

- **HRTF**: 다른 사람의 목소리는 `PannerNode`(`panningModel: "HRTF"`, 브라우저 내장 HRTF, 헤드폰용 앞뒤·고도 단서) + 역제곱 거리 모델(`refDistance` 1.5). 리스너는 원점, 카메라 yaw로 회전 (forward = (sin yaw, 0, cos yaw)). 내 목소리는 패너 없이 정면.
- **봇 = 메아리**: 사인 파형, 저역통과를 `botBlur`만큼 낮추고, 음마다 ±25센트·blur의 느린 디튠 드리프트.
- **방 (잔향)**: 컨볼루션 3개를 신호로 크로스페이드.
  | 방 | 임펄스 | 언제 |
  |---|---|---|
  | 열린 땅 | 1.2 s, 어두움 (저역 필터된 잡음), 초기 반사 없음 | 기본, `(1 − sealed)(1 − hall)` |
  | 콘크리트 | 2.0 s, 밝음, 11 ms 간격 초기 반사 6개 | `sealed` |
  | 홀 | 4.5 s, 긴 감쇠 | `hall = reverbMax × stay × company` (함께 지을 때) |
- **먹먹함**: 마스터 앞 저역통과 하나, 컷오프를 `lpOpen`(8 kHz) ↔ `lpSealed`(600 Hz) 사이 로그 보간 (`sealed`).
- **풀**: 백색잡음 → 밴드패스 2.4 kHz → `noiseMax × grass × 0.5`.

## 8. 엔진 구조 — `engine.ts`

```
[내 목소리] ─ filt ─ gain ──────────────┐
[이웃 n]   ─ filt ─ gain ─ Panner(HRTF) ┤─ dry ──────────┐
[베이스]   ─ gain ──────────────────────┤                │
[패드 5osc] ─ gains ─ level ────────────┤─ rooms: open ──┤─ dull(LP) ─ master ─ out
[풀 잡음]  ─ BP ─ gain ─────────────────┘   concrete ────┤
                                             hall ───────┘
```

- `start()`: 첫 사용자 제스처(pointerdown/keydown/touchend, 모바일 자동재생 규칙)에서 AudioContext 생성·재개, 50 ms 틱 시작, 4초 뒤 Magenta 로드.
- `update(myId, sig, params, yaw, epochMs, key)`: 0.5초마다 (RoleField). 리스너 방향, 먹먹함, 풀, 방 믹스, 이웃 목소리 생성/배치/소멸(1.5 s 뒤), closeness.
- `tick()`: 다음 마디 시작이 0.3 s 안이면 `planBar`로 계획하고 음을 스케줄. 숨은 탭에서 돌아와도 지나간 마디는 건너뛴다(폭주 없음).
- 악기: 삼각파 + 옥타브 사인(`timbre`), 12 ms 어택, 음 길이의 40 % + 150 ms 릴리스. 악기 호출부(`note()`)는 한 곳 → 나중에 NoiseCraft 패치 음색이 필요하면 umwelt `NoiseCraftBridge`(`noiseCraft:setParams`)로 이 함수만 바꿔 끼운다.
- 디버그: 화면 왼쪽 아래 ♪ 줄 — 키·모드, 마디, 코드, lock, 밀도, answer, 이웃 수, path/stay/sealed, Magenta 상태, 진행 중 프레이즈.

## 10. 전체 뷰 (계획, 아직 코드 없음)

## 13. 세션과 소리 — 수명 연동 (v4 A0, 2026-10-15)

세션/역할/수명(`docs/session-logic.md`)이 소리를 이렇게 다룬다 — 소리 자체는 10/14 판 그대로.

- IDLE·DRAW·ENDED: **무음**(`muffleSound` → master 0; 엔진에 id가 비어 있어 마디도 계획하지 않는다 — `tick()`의 `!myId` 가드). LIVE: 첫 마디부터 소리. 마지막 `warnSec`: 둔해짐(저역통과 220/150 Hz로, 전체 × 0.5, 타인 × 0.4, 식생 × 0.3).
- 새 세션 = 새 id = **새 모티프**(RoleField가 세션마다 다시 마운트). 세계 키는 에포크의 것이라 세션이 바뀌어도 같다.
- **♪ 버튼**(`SoundButton.tsx`): 이 창의 음소거/해제. 세션이 켜져 있으면 LIVE에서만, 오른쪽 위(아래는 HUD의 자리). 세션이 꺼져 있으면 아래 가운데. 음소거는 다음 세션으로 이어지지 않는다.
- **ESC**: 세션이 꺼져 있을 때만 음소거 키. 세션이 켜져 있으면 ESC는 시점 풀기(포인터 락) 키이고, **세션을 시작하는 제스처로도 치지 않는다**(`useLifeSession.begin`).
- ♪ 상태줄(왼쪽 위): `♪ 헤드셋 (모바일 뷰) · 재생 중 / 음소거 (♪ 버튼) / 꺼짐 (Leva) / 클릭하면 시작 · <키> · bar … · 세션 <phase> (무음)`.

## 13b. 가볍게 — 소리는 같고 비용만 줄임 (v4 A1, 2026-10-15)

- **Magenta 기본 꺼짐**: 가벼운 버전엔 없다(작가). 켜면 첫 제스처 4초 뒤 tfjs(수 MB, 네트워크)가 로드되어 three.js와 GPU를 나눈다 — 렉의 원인이었다.
- **이웃 목소리 상한 4명**(가까운 순, `MAX_VOICES`): 전에는 `hearRadius` 안의 모두에게 목소리를 만들었다 — 봇 12명이면 패너 12개.
- **패닝 LOD**: 가장 가까운 1명만 HRTF(패너마다 컨볼루션), 2–4위는 equal-power. 순위가 바뀌면 그 자리에서 모델을 바꾼다.
- **홀 잔향 4.5 → 3.0 s**: 컨볼버의 비용은 임펄스 길이다.
- 측정은 **화면이 직접** 한다(`usePerfMeter.ts`, 작가가 DevTools에서 찾기 어려웠다): 왼쪽 위 ♪ 줄 아래 `⏱ 58 fps · 가장 느린 프레임 19 ms · 50 ms 넘는 프레임 0/분 · heap 120 MB`. 렉 = fps가 떨어지고 "50 ms 넘는 프레임"이 쌓이는 것. 각 단계 뒤 LIVE에서 걸으며 봇 끔 / 봇 12명 켬 두 경우를 읽는다(스크린샷이면 충분). DevTools가 필요하면 ⋮ → More tools → Performance monitor(CPU %).

## 14. v4 — 붙이는 순서 (작가 승인, 2026-10-15)

A0 세션 연동(이 절) → A1 가볍게(Magenta 기본 끔, 이웃 캡 4, HRTF는 1위만, 홀 3 s; 작가 기계에서 렉 측정) → A2 NoiseCraft = 정적 기계(`nc_noise_patch` 숨은 iframe, 자기 출력; 화성 시퀀스만 받고 노브·제어값은 안 보냄; 템포는 패치의 클록, Web Audio가 동기) → A3 짧은 모티프(2–4음, 3도 이상 하나) → A4 건물의 조성(조성 거리 알고리즘 `tonality.ts`) → A5 길의 전조(앞의 건물로, 키 경로) → A6 식생 프리레이어 + 드론 → A7 타인(HRTF LOD, 같이 지을 때만 모임) → A8 Magenta(세션 모티프·건물의 주제, 사건마다 한 번) → A9 반주 오스티나토 → A10 스피커. 각 단계 = 커밋 하나 + 이 문서에 절 하나.
