# 사운드 v3 계획 — 모티프는 Web Audio, 화성 존은 건물, 반주는 NoiseCraft (2026-10-15 밤)

작가 (2026-10-15 밤): "내 브라우저는 렉이 아주 심하다. 완전 초기 버전(10/14, `93e85c5`)에서 땅에 코드가 있던 것을 **건물별 화성 존**으로 바꾸고, 흉내낸 부분은 빼고, NoiseCraft가 **모티프와 연동해서 화성에 맞게 반주**하도록 리팩토링하자. Magenta와 타인과의 상호작용(복잡한 부분)은 어떻게 개입시킬지 고민해서 전체 플랜을."

이 문서는 그 플랜이다. 결정되면 단계별로 커밋하고 `sound-logic.md`를 그에 맞게 다시 쓴다(지금 §3·§5·§8·§8b의 상당 부분이 폐기된다).

## 0. 원칙 — 왜 지금까지 꼬였나

하루 동안 쌓인 것: 월드 키 → 홈 키/건물 키 → 융합 → 화성 상태 H(집단·접근·전조·종지) → NoiseCraft 리듬 → 하이브리드 → 한 버스 → 데스크 → 다시 Web Audio. 각각은 피드백에 대한 답이었지만 합치면 **무겁고(렉) 불투명하다(직관성)**. 초기 버전이 더 직관적인 이유는 규칙이 셋뿐이었기 때문이다: 내 모티프가 돈다 / 걸으면 코드가 바뀐다 / 함께 머물면 패드가 난다.

v3의 원칙:
1. **규칙은 다섯 개 이하, 모두 공간에 묶인다** (자리 → 소리). 시간에 묶인 상태 기계(디바운스, 3마디 전조, 반종지)는 뺀다.
2. **들리는 층은 셋**: 내 모티프(Web Audio) / 반주(NoiseCraft) / 이웃의 모티프(Web Audio). 각 층은 한 가지 일만 한다.
3. **흉내는 없다**: Web Audio로 NoiseCraft 텍스처를 흉내내지 않고, NoiseCraft로 모티프 리듬을 흉내내지 않는다. 각자 잘하는 것만.
4. **실시간에 무거운 것은 없다**: Magenta는 실시간이 아니라 **사건마다 한 번**(§5). HRTF·컨볼루션·스트림 라우팅·버스 없음.

## 1. 층 — 무엇이 어디서 울리나

| 층 | 악기 | 내용 | 공간 |
|---|---|---|---|
| **A 나의 모티프** | Web Audio (엔진) | 2–4음 음형(지금의 짧은 모티프, `mark` 포함), 그리드 위에서 밀도(멈춤·걷기·뜀)에 따라; **존의 키로 조적 응답**, 존 밖에서는 홈 키 | 드라이 + 짧은 딜레이 하나 (컨볼버 없음) |
| **B 반주** | NoiseCraft (작은 전용 패치) | 존 안에서만: 코드(건물의 조성) + 베이스 + **모티프에서 파생된 오스티나토**(§3) | 패치 자체의 효과(딜레이·필터). **iframe이 자기 출력으로 바로** 낸다(스트림 라우팅 없음) |
| **C 이웃의 모티프** | Web Audio (엔진) | inner radius 안의 가장 가까운 **2명**, 내 키(존의 키)로, equal-power 패닝 | A와 같은 딜레이 |

스피커(글로벌)는 §6.

## 2. 화성 존 — 땅의 코드를 건물의 존으로

초기 버전의 "땅의 띠"(어디서나 코드가 있고 걸으면 바뀜)를 버리고, **코드는 건물에만** 있다.

```
zone(건물) = { 중심 = 슬래브 셀, 반경 R, 조성 = tonalityOf(기여자들) }
R = R0 + k·질량      (R0 = 6 월드, 질량 = 기여 초의 합 → 큰 건물이 넓게 울린다; 상한 14)
```

- **존 안** (거리 < R): 키 = 존의 조성, 코드 = 기여자 근음들의 코드(지금의 `tonalityOf`, 바꾸지 않음), 반주 B가 울린다. 반주 레벨은 중심에 가까울수록 크다 (`1 − d/R`, 부드럽게).
- **겹침**: 가장 가까운(거리/R이 가장 작은) 존 하나. 경계에서 `0.1·R`의 히스테리시스(지금 `enterAt/leaveAt`의 공간판).
- **존 밖**: 코드 없음. 내 모티프는 홈 키로, 반주는 없다 — 열린 땅은 **화성적으로 비어 있다**. 이것이 "건물 = 화성"을 들리게 한다.
- **길**: 코드 없음(띠 폐기). 길 위에서는 **베이스 펄스**만 — 존 안이면 존의 근음, 밖이면 내 홈 근음. 걷는 리듬이지 화성이 아니다.
- **접근**: 존의 바깥 고리(R < d < 1.3R)에서 반주가 **도미넌트**로 시작해 들어서면 으뜸으로 풀린다 — 유지(가볍고, 도착이 들린다). 그 밖의 전조 절차(피벗·V·I 3마디)는 **폐기**: 존 경계를 넘으면 다음 마디에 바로 새 키.
- **함께 머묾 = 존의 씨앗** (§4): 존 밖에서 사람들이 머물면 그 자리에 **임시 존**(반경 4, 조성 = 머문 사람들의 근음)이 생겨 반주가 작게 난다. 콘크리트가 생기면 그게 건물의 존이 된다. "건물이 태어나는 소리"는 초기 버전의 패드와 같은 자리.
- 지움: 마르코프 진행(`nextDegree`, 띠, `stepEvery`), 반종지/종지, 긴장도 `tension`, 집으로의 전조 3마디, 사람 코드의 2마디 디바운스. `harmonyState.ts`는 **존 계산 + 보이싱**만 남긴다(`leadVoices`는 유지 — 사람이 오갈 때 성부 하나만 움직이는 건 싸고 좋다).

요약하면 H는 `{ zone | null, key, chord, voicing, approach 0..1 }` 로 준다.

## 3. 반주 — NoiseCraft가 모티프와 연동해서 화성에 맞게

반주는 **내 모티프로부터 만든다**. 그래야 "내 것"이면서 "존의 화성"이다.

### 3.1 엔진이 보내는 것 (마디마다, 지금의 드라이버 그대로 — 클록은 패치, 앵커는 엔진)
| 모듈 | 노드 | 내용 |
|---|---|---|
| `harmony` | AI_Poly | 존의 코드 4성 보이싱(`leadVoices`), 마디 홀드(게이트 = 16스텝) — **스웰** |
| `bass` | AI_Seq | 길 위: 근음 펄스(다운비트, 뛰면 중간에도); 존 안 머묾: 근음 홀드 |
| `ostinato` | AI_Seq | **모티프 파생 오스티나토**: 내 모티프의 리듬 셀을 두 번(8스텝 × 2) 반복하고, 음은 모티프의 음정 **방향**을 따라 코드 음 위를 걷는다(위면 다음 코드 음, 아래면 이전) — 한 옥타브 아래. 코드가 바뀌면 같은 걸음이 새 코드 음 위에 놓인다 = 반주가 화성을 따라간다 |
| `traces` | GateSeq | (선택) 이웃들의 리듬 셀 — 렉이 괜찮으면 |

`ostinato`가 "모티프와 연동"의 핵심이다. 같은 사람은 어느 존에 가든 같은 걸음의 반주를, 존마다 다른 음으로 듣는다.

### 3.2 패치 — 전용, 작게
지금 `nc_noise_patch`(235노드, 작가 텍스처 발생기, 딜레이 2단, 스코프들)는 워클릿에서 샘플마다 전부 돈다 — 렉의 큰 몫. **새 패치 `accompaniment.ncft`** 를 만든다(≤ 60노드): AI_Poly `harmony` → 사인/삼각 4성 × 느린 ADSR → 필터; AI_Seq `bass` → 삼각 + 서브; AI_Seq `ostinato` → 짧은 ADSR의 펄스/사인; 딜레이 1개(마디 동기, 노브), 저역통과 1개(노브), 마스터. ClockOut + `seq clock`. 작가의 umwelt 패치는 벤치에서 선택 가능하게 남기되 기본이 아니다.

### 3.3 노브 매핑 (코드, 지금 방식)
`존 깊이(1−d/R)` → 반주 레벨; `접근` → 필터 열림·도미넌트; `머묾×동행` → 스웰 길이; `거칢` → 딜레이 되먹임(식생 가로지르면 번짐); `sealed` → 저역통과. 다섯 규칙이면 된다.

### 3.4 출력
iframe이 **자기 출력**으로 낸다(`out=parent` 끔). 엔진 버스로의 스트림 라우팅·글루·아날라이저는 지운다. 두 소리가 한 방에 있게 하는 것은 **딜레이 시간을 같게**(마디 동기) 하는 것과 레벨 균형으로 한다.

## 4. 타인과의 상호작용 — 세 가지만

복잡했던 것(집단 조성이 열린 땅에서 생김, closeness로 으뜸음이 옮겨감, 답 마디, blend, 흔적, VAE)을 셋으로 줄인다.

1. **들린다**: inner radius(5) 안 가장 가까운 2명의 모티프가 내 키(존의 키, 밖에서는 홈 키)로 들린다. 그 사람의 음형·리듬 = 그 사람. (기존, 싸다.)
2. **머물면 존의 씨앗**(§2): 존 밖에서 1명 이상과 `stay > 0.5`로 머물면 임시 존 — 반주가 작게 시작되고(코드 = 머문 사람들의 근음, 내가 베이스), 떠나면 사라진다. 콘크리트가 생기면 건물의 존으로 굳는다. "함께 짓는다 = 화성이 생긴다"가 공간에서 한 번에 들린다.
3. **부르고 답하기**: 존 안에서 머물 때만, 짝수 마디 나 / 홀수 마디 가장 가까운 이 (기존). 그 외에는 모두 동시에.

지움: `closeness`로 섞이는 `blend`(미세해서 안 들렸다), 열린 땅의 집단 조성, 내 음역의 재앵커(`anchorBase` — 존 경계에서 첫 음만 코드 음으로 당기는 `lockPull`로 충분), 반음 예산의 긴장 연동, 확대/단편화(밀도만 남김).

## 5. Magenta — 실시간이 아니라 "사건마다 한 번"

실시간 Magenta(tfjs가 three.js와 GPU를 나눔)는 렉의 원인이고, 매 마디 프레이즈를 바꾸는 것은 정체성을 흐렸다. v3에서 Magenta는 **작곡가**다 — 드물게, 한 번에, 결과는 저장.

| 사건 | 무엇을 | 어떻게 | 어디서 들리나 |
|---|---|---|---|
| **건물이 태어날 때** (첫 콘크리트) | **건물의 주제** = 기여자들의 모티프를 MusicVAE로 보간(2명이면 중점, 3명 이상이면 무게 순으로 차례로) → 2마디 프레이즈 | 한 번 계산(수백 ms, 그 순간만 GPU), 결과를 로그에 이벤트로 기록(`k:"theme"`, 슬래브 키, 32스텝) — 모든 탭·스피커가 같은 주제를 읽는다 | 존 안에서 반주 패치의 `ostinato` 대신(또는 번갈아) — 건물에 들어가면 **그 건물의 노래**가 난다. 기여자가 늘면(무게가 바뀌면) 다시 한 번 |
| **오래 함께 있을 때** (closeness ≥ 0.8, 한 번) | **둘의 선** = 내 모티프 ↔ 그 사람 모티프의 VAE 보간 ½ | 한 번 계산, 세션 동안 캐시 | 그 사람과 같은 존에 있을 때 Web Audio의 둘째 목소리(`line`)로 4마디, 그 뒤 쉼 |
| MusicRNN 즉흥 | **폐기** | — | (코드 위 즉흥은 정체성을 지우고, 실시간이었다) |

실패(네트워크·GPU 없음)하면 조용히 없음 — 반주는 §3의 오스티나토로 충분하다. 전시에서는 **주제를 미리 계산해 두는** 것도 가능(봇·과거 방문자의 건물).

## 6. 스피커 (글로벌 뷰)
지금 `global.ts`(덩어리·흔적·뭉침·숨)는 Web Audio이고 가볍다. v3에서 바꾸는 것 하나: 각 사람의 키가 "홈 키 / 건물의 키"에서 "홈 키 / **존**의 키"로 — 코드가 §2와 같아진다. 건물의 주제(§5)가 있으면 그 건물 위치에서 낮게 돈다. NoiseCraft 글로벌 패치는 보류.

## 7. 렉 — 예산과 제거 목록

이 쪽 브라우저에선 봇을 켜도 60 fps라 작가 기계의 병목을 **측정**해야 한다: Chrome 작업 관리자(⇧Esc)에서 탭별 CPU/GPU, 그리고 플레이어 탭의 `?ui=0`(Leva 없음)과 봇 끔으로 비교. 그 결과와 무관하게 v3가 지우는 것:

| 지움 | 이유 |
|---|---|
| NoiseCraft **큰 패치**(235노드) → 작은 전용 패치(≤ 60) | 워클릿의 샘플당 JS가 1/4 |
| 패치 스트림 → 엔진 버스 라우팅, 글루 컴프, 아날라이저 2개, 트랙 미터 | 미디어 파이프라인 + 지연. iframe이 직접 출력 |
| 컨볼버 3개(룸) → 딜레이 1개 | 컨볼루션 = 가장 비싼 노드 |
| HRTF 패너 → equal-power (완전히) | 패너마다 컨볼루션 |
| 마디 에코의 되먹임 체인, 텍스처 방울, 숨쉬는 음색 | 흉내·장식 |
| 실시간 Magenta | GPU 경합 |
| 버스(BroadcastChannel) 송신은 **벤치가 열려 있을 때만** | 메시지 2 Hz도 안 보내는 게 낫다 |
| 봇당 `motifOf`·closeness 갱신을 0.5 s → 1 s | 미세 |
| Leva 입력 수 절반 | 리렌더 |

예상: 엔진 노드 수 ~1/3, 워클릿 부하 ~1/4, 메인 스레드 메시지 ~0. 그래도 렉이 남으면 사운드가 아니라 씬(봇 수·DPR·fold)이고, 그건 세션/수명 세션과 같이 본다.

## 8. 단계 (각 단계 = 커밋 하나 + `sound-logic.md` 갱신)

| 단계 | 내용 | 지우는 파일/코드 | 작가가 듣는 것 |
|---|---|---|---|
| **P0 가볍게** | 텍스처·에코·HRTF·룸 컨볼버·스트림 라우팅·글루·미터·데스크 잔재 제거; 딜레이 하나; 버스는 벤치 있을 때만 | engine.ts 절반, bus 사용처, SoundControls 미터 | 렉이 줄었는지 — 여기서 측정부터 |
| **P1 존** | `zones.ts`: 건물의 존(반경·조성·깊이·접근), 임시 존(머묾), H = 존; 띠·마르코프·종지·전조·긴장 제거 | harmonyState.ts 대폭 축소, harmony.ts의 world/band 코드 | 건물에 들어가면 화성, 나오면 모티프만 |
| **P2 반주** | `accompaniment.ncft` 전용 패치, 모듈 `harmony/bass/ostinato`, 오스티나토 생성(`accompany.ts`: 모티프 → 코드 위 걸음), 노브 다섯 규칙, iframe 직접 출력 | noisecraftMap 축소, 큰 패치는 벤치 전용 | 내 모티프의 걸음이 건물의 코드 위에서 반주로 |
| **P3 타인** | 들림(2명)·존의 씨앗·부르고 답하기만; blend·재앵커·긴장 예산·확대/단편화 제거 | sequencer.ts·motif.ts 축소 | 둘이 머물면 화성이 싹트고 콘크리트로 굳는다 |
| **P4 Magenta** | 건물의 주제(VAE, 탄생 시 한 번, 로그 이벤트), 둘의 선(한 번) ; RNN 제거 | magenta.ts 절반 | 건물마다 노래가 있다 |
| **P5 스피커** | 존의 키, 건물 주제의 저음 | global.ts 소폭 | 방에서 건물들이 각자 울린다 |

P0–P1은 하루 안, P2는 패치 작업 포함 하루, P3·P4 각각 반나절.
