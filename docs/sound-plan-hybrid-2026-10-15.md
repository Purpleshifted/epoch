# 하이브리드 계획 — 화성은 NoiseCraft로, 라이트모티프는 Web Audio로 (2026-10-15)

> **상태 (같은 날 저녁)**: 작가 "나머지는 알아서 음악적으로 진행하고 보고해줘" → 0–3단계 구현됨 (`sound-logic.md` 변경 이력 (7)). 계획과 달라진 점: `nodeP`(길 그래프 노드) 대신 **길에서 멈춤 = 반종지, 길을 벗어남 = 종지**로 종지를 냈고(그래프 없이 가능), Magenta가 화성 층에 자리를 얻었다(§4 `line`: RNN이 내 모티프를 장소의 코드 위에서 즉흥 — 진행이 선으로 들린다). 4단계(스피커)는 남음. 작가에게 묻는 것 §8은 기본값으로 정해 두었다: 1 예(가까운 이웃은 Web Audio, 먼 이웃은 흔적), 2 도미넌트 준비, 3 피벗이라 즉시(단 2마디 디바운스), 4 패드는 꺼지되 패치의 텍스처가 남음, 5 코드 음만.

작가 피드백: NoiseCraft로 리듬을 살리고 나니 소리가 **얇아졌고**, 라이트모티프에 패치의 리버브·딜레이가 세게 걸려 **어색하다**. 제안: 화성 변화의 영향을 받는 음(코드·베이스·패드·텍스처)은 NoiseCraft에, 라이트모티프는 Web Audio로 **병렬**. 이 문서는 그 제안을 받아 **화성 변화와 멜로디 변화의 로직**을 다시 세우고 단계별 계획을 적은 것. 살아 있는 규칙은 확정될 때마다 `sound-logic.md`로 옮긴다.

## 0. 진단 — 왜 얇아지고 어색해졌나

| 증상 | 원인 | 교훈 |
|---|---|---|
| 모티프가 어색함 | 패치의 체인(딜레이 2단 + 리버브 + 디스토션)은 **장(field)** 을 만들려고 짜인 것인데, 그 위에 **정체성**인 멜로디를 얹었다. 정체성은 가깝고 건조해야 "이 사람의 목소리"로 들린다 | 멜로디 = 드라이·가까움·정위. 화성 = 젖고 넓음 |
| 소리가 얇아짐 | ADSR 넷을 패치의 랜덤 트리거(Mul 24/43/115)에서 떼어 시퀀서 게이트에 물였다 → 작가가 만든 **보글거리는 텍스처**가 사라지고, 성부마다 음 하나만 남았다 | 작가의 트리거 체인은 그대로 두고, 그 **음높이**를 화성에서 받으면 된다 (umwelt에서 원래 그렇게 썼다: AI_Seq는 freq만 쓰고 gate는 안 썼다) |
| 그래도 리듬은 들려야 함 | 라이트모티프의 리듬·길이는 Web Audio가 정확히 낸다(지금 코드가 이미 그렇다). NoiseCraft에는 GateSeq로 **흔적**만 | 리듬의 주체는 멜로디 층, NoiseCraft는 흔적과 스웰 |

결론 — **역할 분담**. NoiseCraft의 강점(작가의 텍스처·효과·진화하는 장)과 Web Audio의 강점(정확한 타이밍, 드라이, id별 음색, HRTF 정위)을 각자 맡긴다. 둘은 같은 클록 위에서 같은 화성 상태를 읽는다.

## 1. 층 — 무엇이 어디서 울리나

| 층 | 악기 | 내용 | 공간 | 신호 |
|---|---|---|---|---|
| **멜로디** | 헤드셋 · Web Audio | 내 라이트모티프 + **inner radius 안**의 이웃들의 라이트모티프 | 나: 드라이, 중앙, 가까움 (리버브 거의 없음). 이웃: HRTF로 그 사람 쪽에서 | 화성 상태 H(§2) + 걷기·머묾·동행 |
| **화성** | 헤드셋 · NoiseCraft (`nc_noise_patch`) | 코드 패드(보이싱된 4성, 변화 때 스웰), 베이스(길의 근음 펄스), **텍스처**(작가의 랜덤 트리거가 치는 성부들 — 음높이는 코드의 음 집합에서), 먼 이웃들의 **리듬 흔적**(GateSeq → 작가가 꽂는 무엇이든) | 젖고 넓음 (딜레이·리버브는 여기) | H + 모드·거칠기·동행 노브 |
| **세계의 장** | 스피커 · NoiseCraft (`global_audio`) | 모든 건물의 조성을 질량으로 섞은 **느린 진행** + 모두의 리듬 흔적. 멜로디 없음 (익명의 소음 풍경) | 방 전체 | 세계 H (§2.9) |

전시에서: 헤드셋을 쓴 사람은 "내 목소리가 화성 속에서 어디 있나"를 듣고, 벗으면 방 전체의 장만 남는다.

## 2. 화성 상태 H — 정의와 동인

```
H = {
  key:        { root, mode }                      // 지금 내가 있는 조
  chord:      { classes[], root, voicing[4] }     // 지금의 코드와 4성 보이싱(MIDI)
  bass:       midi                                // 근음(또는 5음)
  tension:    0..1                                // 긴장도
  cadence:    null | "half" | "full"              // 이 마디가 종지인가
  modulation: null | { from, to, pivot, bar }     // 전조 진행 중이면
  changedBar: number                              // 코드가 마지막으로 바뀐 마디
}
```
마디마다 순수 함수 `harmonyState(prev, sig, who, bar)` 가 만든다 (새 모듈 `harmonyState.ts`; 지금 `engine.ts` 안에 흩어진 placeKey / placeChord / degree / walked 를 여기로 모은다). 두 악기와 스피커가 **같은 H**를 읽는다.

### 2.1 하나의 원리 — 조성은 언제나 "누구의 무게"다
지금 `tonalityOf(builders)` 는 건물에만 쓴다. 이를 일반화한다: **조성 = 무게 있는 사람들의 홈 근음 집합**.

| 상황 | 무게 집합 | 결과 |
|---|---|---|
| 홀로, 열린 땅 | {나: 1} | 내 홈 키 |
| 이웃과 머묾 (build 모드) | {나: 1, 이웃: 가까움·머문 시간} | 집단의 조성 — 가장 무거운 사람의 근음이 으뜸음, 코드 = 근음들 |
| 건물 앞 | {기여자들: 기여 무게} (+ 지금 서 있는 사람들: 작은 무게) | 건물의 조성 (지금 로직) |
| 세계 (스피커) | {건물들: 질량} → 건물마다 위의 집합 | 세계의 장 |

이러면 "사람들이 모여 → 집단의 조성 → 짓기 시작하면 건물의 조성으로 **굳는다**"가 한 함수로 이어진다. 건물은 결정(結晶)된 집단이다.

### 2.2 코드와 보이싱 — 사람이 성부다
- 코드의 음 = 무게 집합의 근음들 (≤ 4, 부족하면 3화음으로 채움 — 지금과 같다).
- **보이싱**: 가장 무거운 사람의 근음 = 베이스. 가장 **최근에 온** 사람의 근음 = 맨 위 성부 (새로 온 사람이 위에서 들린다). 나머지는 사이.
- **성부 진행(voice leading)**: 코드가 바뀌면 4성 각각이 **가장 가까운** 새 코드 음으로 간다 (대개 ≤ 2반음). 한 사람이 떠나면 그 성부만 빠지고 나머지는 움직이지 않는다 — "한 사람이 나갔다"가 들린다.
- 패드(NoiseCraft `harmony` 모듈)는 이 보이싱을 그대로 받는다. 게이트 = 마디 전체(홀드), 바뀐 마디만 다시 어택(스웰).

### 2.3 화성 리듬 — 얼마나 자주 바뀌나
| 상황 | 코드 변화 |
|---|---|
| 길 위 | `stepEvery` 걸을 때마다 (지금 로직), 단 **마디 머리**에서만 |
| 건물 / 집단 | 무게가 바뀔 때마다, 단 **2마디에 한 번 이하** (디바운스 — 사람이 들락거려도 코드가 떨리지 않게) |
| 열린 땅 | 4마디마다 한 번 (I ↔ 드론) |
| 전조 | 한 번에 3마디 (§2.6) |

### 2.4 길 = 진행, 교차로 = 종지
- 길을 따라 걸으면 지금의 마르코프(T→S→D→T 성향)로 도수가 나아간다 — 유지.
- **길이 갈라지거나 끝나는 지점(그래프의 노드)에 닿으면 종지**: D → I (full) 또는 I → V (half, 계속 갈 때). 걷는 사람에게 길의 마디(句讀)가 들린다. 길 그래프는 이미 있다(`pathP`가 거기서 나온다) — 노드 근접 신호 `nodeP` 하나만 더 뽑으면 된다.

### 2.5 접근 = 도미넌트 준비, 도착 = 해결
건물에 **다가가는 동안**(거리 r₁ < d < r₂) 코드는 그 건물 조성의 **V**(또는 V7)로 간다. 들어서는 순간(거리 < r₁, 히스테리시스 유지) 건물의 코드(I 위치의 근음 코드)로 **해결**된다. 그래서 건물에 도착하는 것이 종지로 들린다. 떠날 때는 반대로 하지 않는다 (떠남은 조용히, 그냥 홈 키로 돌아감 §2.8).

### 2.6 전조 절차
키 K₁ → K₂:
1. 마디 0: **피벗 코드** — 두 키에 다 있는 3화음 중 가장 가까운 것. 건물/집단의 코드는 **구조상 피벗**이다(근음들은 그대로이고 으뜸음 해석만 바뀐다) — 그래서 건물 안에서 다수가 바뀌어 으뜸음이 옮겨가도 부드럽다.
2. 마디 1: K₂의 V (접근 중이면 §2.5가 이미 여기 있다).
3. 마디 2: K₂의 I.
열린 땅에서는 새 장소에 **2마디 이상** 있어야 전조가 시작된다 (히스테리시스는 지금 `sealRadius` 방식 그대로). `modulation` 필드는 NoiseCraft 노브(스윕)와 멜로디(§3)가 읽는다.

### 2.7 긴장도
```
tension = 0.5·func(degree)            // I 0, vi/iii 0.2, ii/IV 0.4, V/vii 0.8 (단조는 표가 다름)
        + 0.3·approach                // 건물에 다가가는 정도 (§2.5)
        + 0.2·rough                   // 식생을 가로지르는 거칠기
```
쓰임: 패드 밝기(NoiseCraft 필터·리버브 노브), 멜로디의 반음 예산(§3), 스피커의 장. 종지에서 0으로 떨어지는 것이 "도착"이다.

### 2.8 열린 땅 / 식생
화성이 **옅어진다**: 패드 레벨 ↓, 코드는 으뜸음 드론 또는 없음, 베이스 없음. `tension` 은 거칠기에서만 온다. 4마디 뒤에 홈 키로 되돌아가는 전조(§2.6)가 시작된다 — 돌아오는 길은 늘 집으로.

### 2.9 스피커 — 세계의 장
`global_audio` 는 사람 하나의 H가 아니라 **세계의 H**를 읽는다: 건물마다 §2.1의 조성, 건물의 질량(기여 초)으로 가중 → 가장 무거운 건물의 키가 방의 키, 나머지 건물의 코드들이 **느린 진행**(8마디에 한 번, 질량 순으로 순환). 리듬 흔적(모두의 셀)은 GateSeq `traces` 로. 멜로디는 없다. 지금 `global.ts`(MASS/TRACES/CLUMPS/BREATH)의 Web Audio 판은 NoiseCraft 판이 설 때까지 폴백.

## 3. 멜로디 변화 M — 무엇이 변하고 무엇은 절대 안 변하나

### 3.1 불변 (정체성)
음정 클래스의 열(실음정 모양), 윤곽(오르내림), 리듬 셀, 색(cents), 음색, 템포 스케일. 테스트가 지킨다: 어떤 H에서 실현해도 윤곽 100 %, 음정 클래스 ≥ 80 % 보존, 리듬 셀은 그대로이거나 **확대**(augmentation)이거나 **머리만**(fragmentation)이다.

### 3.2 변하는 것 — 동인과 음악적 이름
| # | 변화 | 동인 | 지금 | 계획 |
|---|---|---|---|---|
| 1 | **조성 응답** — 모양을 지금 키의 음계로 | H.key | `tonalAnswer` (있음) | 유지 |
| 2 | **앵커 / 동형진행(sequence)** — 첫 강박 음을 코드 음에, 직전 마디 끝음에서 가장 가깝게 | H.chord, 직전 마디 | 없음 (매 마디 base에서 시작) | 핵심 추가. 진행을 따라 모티프가 "옮겨 앉는" 것이 멜로디가 화성을 따르는 가장 고전적인 방식 |
| 3 | **강박의 코드 당김** | lock(순응) | `pullToChord` (있음) | 유지, 강박 정의를 셀의 첫 음·중간 음으로 |
| 4 | **반음 예산** | tension, rough | 상수 1 | `budget = round(1 + 2·tension + 2·rough)`: 안정된 I 위에선 거의 온음계, 긴장·거칠면 색이 들어온다 |
| 5 | **밀도·템포** | speed | `density` (있음) | 유지 |
| 6 | **확대(augmentation)** | 머묾(stay) 높고 속도 0 | 없음 | 셀을 2배로 늘려 한 마디에 반만 (느리게 숨쉬는 모티프) |
| 7 | **단편화(fragmentation)** | 빠름 + 거침 | 없음 | 머리 2–3음만 반복 — 달리며 가로지르면 모티프가 조각난다 |
| 8 | **장식(passing tones)** | 안정(lock 높음) + 느림 | 없음 | 4반음 넘는 도약 사이를 온음계로 채움, 약박에 |
| 9 | **음역** | sealed, 건물 높이 | 없음 | 건물 안에선 한 옥타브 아래(둘러싸임), 높은 건물 위층은 위로 |
| 10 | **종지 착지** | H.cadence | 없음 | full 종지 마디의 마지막 음을 으뜸음/3음으로 — 도착이 멜로디에서도 들린다 |

### 3.3 타인과
- **응답 마디**(staying + 홀수 마디) 유지: 내가 쉬고 가장 가까운 이가 답한다.
- **빌려오기** `blend`(가까움·시간) 유지. Magenta는 기본 꺼짐 그대로.
- **리듬 모방**: 응답 마디에서 내 다음 마디는 상대의 셀로 한 번 (리듬 흔적이 내 안으로). inner radius 밖의 사람들은 멜로디가 아니라 NoiseCraft의 `traces` 로만.

### 3.4 순서 (한 마디를 만드는 파이프라인)
`H` → 모양에 조성 응답(1) → 앵커·동형진행(2) → 강박 당김(3, lock) → 반음 예산 안에서 색(4) → 밀도/확대/단편화(5–7) → 장식(8) → 음역(9) → 종지 착지(10) → 거칠기 흔들림. 각 단계는 순수 함수, 각각 테스트.

## 4. NoiseCraft가 받는 것 — 모듈과 노브

지금 모듈: `parliament`(poly: 나, n1–n3), `me`, `n1–n3`, `bass`, `pad`. 하이브리드에서 NoiseCraft는 **멜로디를 받지 않는다** (받고 싶은 패치는 `parliament`를 그대로 고를 수 있다 — 호환 유지).

| 모듈 | 노드 | 내용 | 게이트 |
|---|---|---|---|
| `harmony` | AI_Poly | H.chord.voicing (4성, 성부 진행된) | 마디 전체 홀드; 바뀐 마디만 재어택 (스웰) |
| `bass` | AI_Seq | 길에선 근음 펄스(다운비트·중간), 건물에선 홀드 | 길이 1.5스텝 / 홀드 |
| `texture` | AI_Poly | 코드 음 집합을 두 옥타브에 펼친 4음 (음높이만) | **게이트 안 씀** — 작가의 랜덤 트리거가 ADSR을 친다. 화성이 바뀌면 텍스처의 음 집합이 바뀐다: 화성 변화가 "장"으로 들린다 |
| `traces` | GateSeq (이름으로 수신, 이미 됨) | inner radius 밖 이웃들 + 나의 리듬 셀, 행 = 사람 | 작가가 행 출력을 무엇에든 꽂는다 (노이즈 버스트, 퍼커시브 필터…) |

노브 규칙(코드, `noisecraftMap.ts`)에 추가: `tension`(필터·리버브), `modulating`(전조 3마디 동안 0→1→0: 스윕), `cadence`(종지 마디 펄스), `consonance`(내 모티프의 현재 음과 코드의 거리 — 디스토션), `company`(동행 수).

`nc_noise_patch` 배선 계획(작가와 편집기에서): ADSR 90/89/124/289의 gate를 **작가의 랜덤 트리거로 되돌리고**, 그 성부들의 freq를 `texture` 모듈에서; AI_Seq 257(voice 1)을 `bass`로 바꾸고 gate는 시퀀서 gate 유지; `harmony` AI_Poly 하나를 새로 놓아 패드 체인(Vol CHORDS 183)에; GateSeq `parliament`는 `traces`로 이름만 바꾼다. 즉 **지난 커밋의 리듬 배선을 멜로디에서 걷어내고 화성에 쓴다** — 포크의 개량(게이트 = 길이, GateSeq 수신, 폴백 수정, 편집기 재생성 제거)은 모두 그대로 필요하다.

## 5. 두 악기의 동기
- NoiseCraft가 마스터 클록(ClockOut 펄스, 오디오 시간) — 유지. 드라이버가 펄스의 오디오 시간과 벽시계를 함께 받으니, 엔진은 `마디 시작(벽시계) → 자기 AudioContext 시간`으로 환산해 Web Audio 음을 예약한다. 오차는 메시지 지연 몇 ms — 리듬 층은 멜로디(Web Audio) 한 곳에만 있으니 들리지 않는다.
- NoiseCraft가 없는 창(패치 안 고름, 또는 iframe 실패)에서는 지금처럼 Web Audio가 자기 벽시계 격자로 — 폴백.
- 두 AudioContext는 섞이지 않는다(모티프에 패치 효과를 걸 수 없다). 모티프의 공간감은 Web Audio의 짧은 컨볼루션 하나로 충분하다.

## 8. 작가에게 묻는 것
1. 가까운 이웃(inner radius 안)의 모티프도 Web Audio로 — 맞나? (그래야 "누가 어디서"가 들린다.) 먼 이웃은 리듬 흔적만.
2. 접근 = 도미넌트 준비(§2.5): 건물에 다가갈 때 긴장이 오르고 들어서면 풀리는 것 — 원하는 느낌인가, 아니면 건물은 그냥 "다른 조"로 조용히 넘어가야 하나.
3. 건물 안에서 다수가 바뀌어 으뜸음이 옮겨갈 때(§2.6) — 즉시(피벗이니 부드럽다) vs 2마디 디바운스.
4. 열린 땅에서 화성이 옅어지는 것(§2.8) — 패드가 아예 꺼져도 되나, 드론 하나는 남겨야 하나.
5. 텍스처 성부의 음 집합(§4 `texture`): 코드 음만 vs 음계 전체(더 "소음 풍경"에 가까움).
