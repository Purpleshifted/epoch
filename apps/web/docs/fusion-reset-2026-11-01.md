
## 7. 가설 (융합 세션, 15:30, 코드 근거 — 기준선에서 확인)
- **(a) 부재 13.7k → 40.8k(30분)는 정상 성장**: 상주 봇 20명 · 4무리 · 방문자 3명 기준이면 그 값.
- **(b) 워커 125 ms → 11.7 s(90배)는 부재 3배로 설명 안 됨.** 후보 ① 요청 합치기의 자가 증폭 — 계산이 틱(0.5 s)을 넘기 시작하면 버려진 요청의 식생·융합 작업이 매 계산에 붙어(4번에 1번 → 매번) 더 느려지고 더 붙음. ② 융합 청크의 복셀 격자가 그 청크가 아니라 세계 전체 footprint로 잡혀 봇이 퍼질수록 청크당 비용이 면적에 비례(voxel 0.25면 4배).
- **(c) 띠가 비는 경로 = 카메라 LOD 뒤집힘**: 자동 운행 카메라가 멀어지면 모든 부재가 통짜로 다시 생성 → 모든 청크 키가 바뀌어 stale, 흡수 기억이 사라져 흡수된 부재가 되살아남 → 2청크/11.7 s로 띠를 다시 짓는 1~2분 동안 "융합 없음". (970146b의 고정 키 수정이 롤백으로 빠진 상태.)
- **기준선에서 가르는 법**: A(기본값)에서 worker ms가 시간에 따라 어떻게 커지는지 → (b)①②. `?cam=band`(자동 운행 끔)에서 띠가 안 비고 자동 운행을 켜면 비면 → (c).
- **고치는 방향(동결 해제 뒤, 각각 한 커밋 + 테스트)**: ① 합치기에서 식생·융합을 누적하지 말고 시간 cadence로(식생 ≥ 2 s · 융합 ≥ 1 s) ② 부재가 전부 ≥ 0.98 부식인 청크는 다시 짓지 않음(예산을 전이 띠에) ③ 흡수 기억을 부재 고정 키로 + LOD 뒤집힘 때 융합 키 유지 ④ 청크 복셀 격자를 그 청크 부재들의 bbox로.
- **검사 스위치(e9e9fb7, 뷰만)**: `?presets=default`, 상태줄 `preset: server HH:MM / local / default · tab-modified · cam=band`, `?cam=band`(초점 −45 · 62° · 거리 120 · 자동 운행 끔 · 회전 0).
